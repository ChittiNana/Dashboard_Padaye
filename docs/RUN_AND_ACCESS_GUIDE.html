Prerequisites

  • Node.js 18+ and npm (comes bundled with Node)
  • Git, and access to clone github.com/ChittiNana/Dashboard_Padaye
  • No backend/database needed — the app works stand-alone (see "About the demo data" below)
2

Run it locally

git clone https://github.com/ChittiNana/Dashboard_Padaye.git
cd Dashboard_Padaye
git checkout feature/ui-mock-data-layer

npm install
npm start

This opens the Create React App dev server. It automatically launches your browser at http://localhost:3000 — if it doesn't, open that URL yourself.

The terminal will print two URLs once it's ready — something like:
Local:    http://localhost:3000
On Your Network: http://192.168.x.x:3000
Keep that second one handy — it's what other devices on your Wi-Fi use (see below).

To stop the server, go back to that terminal and press Ctrl+C.

Open it on your phone or another laptop (same Wi-Fi)

The dev server is reachable by any device on the same Wi-Fi/LAN as your laptop — no extra tools needed.

  1. Make sure your phone/other laptop is connected to the same Wi-Fi network as the laptop running npm start.
  2. On that other device's browser, go to the On Your Network URL printed in the terminal, e.g. http://192.168.1.42:3000.
  3. If this is the first time, Windows may show a Windows Defender Firewall prompt asking to allow Node.js on private/public networks — this only appears on the laptop running the server, and only someone with permission to click through it should accept it.
⚠️ On an office/managed laptop, don't change firewall rules yourself if the prompt is blocked or you're unsure — check with IT first. Many corporate Wi-Fi networks also enable client isolation, which blocks device-to-device connections entirely even with the firewall allowed — if the LAN URL doesn't load from another device, this is the most likely reason, and it isn't something you can fix from your laptop. Use the tunnel option below instead.
5

Share it with someone outside your network

For a viewer who is not on your Wi-Fi (a different office, home, another city), use an outbound-only HTTPS tunnel — it needs no firewall changes and no router/port-forwarding setup, since the connection is initiated from your laptop outward.

Option A — ngrok

# one-time: create a free account at ngrok.com and copy your authtoken
ngrok config add-authtoken <your-token>

# with "npm start" already running on port 3000, in a second terminal:
ngrok http 3000

ngrok prints a public URL like https://abcd-1234.ngrok-free.app — share that link; it forwards straight to your local dev server.

Option B — Cloudflare Tunnel (no account needed for a quick link)

cloudflared tunnel --url http://localhost:3000
Only run a public tunnel from a machine and account you're allowed to install this kind of tool on — not on a managed corporate laptop without checking policy first. Anyone with the generated link can reach your running app for as long as the tunnel and dev server stay up, so close the tunnel when you're done demoing.

About the demo data

  • Everything you create, edit, or delete (students, attendance, fees, notices, question papers…) is saved instantly in your browser's local storage, under the key padaye_mock_store_v1.
  • It survives logging out and logging back in as a different role — e.g. a teacher adds a student, logs out, and the principal immediately sees it.
  • It survives a page reload too — it's not held only in memory.
  • It auto-resets after 24 hours back to the original demo dataset, so stale test data doesn't pile up.
  • Each browser (and each incognito/private window) has its own separate copy — data created on one device/browser won't appear on another.

Troubleshooting

"Something is already running on port 3000"

A previous npm start is probably still running (e.g. in another terminal, or a stale window). Find and close it, or let Create React App prompt you to run on the next free port instead.

Phone/laptop on the same Wi-Fi can't load the page

Check, in order: both devices on the exact same Wi-Fi network; the firewall prompt wasn't dismissed/blocked; the network doesn't enforce client isolation (common on corporate/guest Wi-Fi — switch to the tunnel option instead).

Login fails for a valid demo account

Double check the username/password are typed exactly as in the table above (all lowercase, no spaces).

My changes disappeared

Either more than 24 hours passed since the data was last seeded (auto-reset), or you're viewing from a different browser/device than the one you made the change on.
